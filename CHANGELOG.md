# Changelog

Significant changes only (CLAUDE.md rule 5): one line per change, 1–2
sentences — essence and intent, not content.

- 2026-07-21: Every hosted demo now serves a public web ROOT page at `/` — a self-contained, CDN-free info page a human/AI-assistant visitor lands on: the demo's name + one-line service framing, live DOMAIN activity counters read server-side from that demo's OWN tables (not telemetry — e.g. skooti fleet + rides, atablefor tables/covers, hoteling rooms/nights, philslist listings, tudu lists/todos/members), and a copy-pasteable "poke it" section pointing at `/.well-known/kiosk.json` + `/kiosk/schema` + the skill. Created a root for the four API-only/proc-root demos (atablefor, skooti, hoteling, philslist, stylish) and augmented getgrocery's storefront + tudu's web UI with the stat cards.
- 2026-07-21: Hosted-demo pre-HN features — a per-demo `KIOSK_POW_DIFFICULTY` knob (default `low`, opt-in `high` maps to the heavy Equihash 168/7 for skooti + atablefor with an honest "beware: intensive PoW" banner in `/.well-known/kiosk.json`, unset = low so CI stays fast), and opt-in, app-layer, privacy-safe live-activity telemetry (a shared append-only events store + a per-demo Rack hook recording one generic event per successful wire action under a per-app-salted, non-cross-app-joinable agent hash, an aggregate `GET /demo/activity.json`, and a seed/simulate task) wired into all seven demos and gated OFF by default (`KIOSK_TELEMETRY=1`).
- 2026-07-20: Re-pinned all seven demos (and the engine default skill URL) to the immutable `skill-v0.3.1` — the "agent" → "AI assistant" terminology pass reached the skill; demo READMEs/before-after adopt the same voice, and the hoteling/skooti stub READMEs were fleshed out to match their siblings.
- 2026-07-20: Bumped the wire to protocol 0.3.0 (`API_VERSION`/`MIN_CLIENT`) — a backward-compatible feature-milestone MINOR over 0.2 (KYC, roles-from-IdP, per-assistant spending caps, the non-commerce demos) with no breaking wire change; re-pinned all seven demos to the new immutable `skill-v0.3.0`.
- 2026-07-20: Reframed the food-delivery demo into `kiosk-demo-atablefor`, a restaurant TABLE-BOOKING provider (Mamma Pizza now takes reservations) — the "book a table for two tomorrow at 8" flagship story, with a four-verb no-payment surface (availability/my_bookings queries, book_table/cancel_booking actions; `pay` absent from advertised capabilities), PoW + a reputation curve reframed as anti-reservation-scalping, and owner-scoped isolation; the suite's single RLS *showcase* moved to getgrocery's new `demo:rls` task.
- 2026-07-19: getgrocery boots out-of-box like its siblings — in dev/test it uses a placeholder Stripe key when none is set, so demo:setup/schema/isolation run with no payment config; only a real charge (demo:shop) needs a live key or stripe-mock.
- 2026-07-19: KYC attestations can now carry named anonymized `attributes` ({name: true} booleans, e.g. age_over_18/licence_a) alongside the binary `level`, so an action can gate on required attributes and reject with the new `kyc_required` (403) wire error without ever learning the underlying documents; demonstrated by the skooti `rent_motorcycle` gate.
- 2026-07-19: A provider can cap each bound assistant's payments through the core `config.spending_cap` pay-hook seam, so a human governs (or disables) an assistant's spend; the pay path rejects an over-cap charge with the new `spending_cap_exceeded` (403) error before the irreversible capture.
- 2026-07-19: Re-pinned the skill to v0.2.4 — the default `skill_url` and all seven demos now advertise `skill-v0.2.4.md` and its SHA-256, keeping the dual-check pin in sync with the re-versioned skill (terminology + three additive 0.3-feature notes).
- 2026-07-19: roles-from-IdP (indirect, via the bound human) — the account-binding link ceremony now carries the signed-in human's `user_idp` role onto the link row and sets the bound agent's `allowed_roles` from it (fresh key: linked with that role; rebind: adopts the new human's role), so a provider whose IdP reports roles provisions an assistant's role without the agent ever self-selecting it; role-less/single-role providers are unchanged. Demonstrated in `kiosk-demo-stylish`, now dual-audience: salon staff (owner/stylist) sourced from a role-carrying StubUserIdp, a role-gated `salon_calendar` query (owner: whole book + revenue; stylist: own chairs), plus `demo:roles` and a redteam beat proving the gate is un-bypassable.
- 2026-07-19: Renamed the salon-booking demo `kiosk-demo-saas-booking` → `kiosk-demo-stylish` — the service now carries the coined brand "stylish" (a hair-styling booking service) while the seeded salon stays "Combette on Park"; database names, module, CI matrix, and cross-demo references updated to match.
- 2026-07-19: Account-binding rebind now watermark-revokes the key's pre-link tokens, exactly as unlink does — a claim is a principal change, so the agent must re-login for a token under the new holder rather than keep authenticating as the old principal.
- 2026-07-19: New `kiosk-demo-tudu` — a NON-COMMERCE collaborative todo app proving the four-verb surface carries multi-user collaboration with NO payments: membership-based many-to-many access (not just owner-scoped rows), agent→agent list invites over `run` (single-use codes, pure app-layer, no spec change), per-agent attribution, and the first real use of the W5 `assistant_claimed` rebind hook to migrate a headless account's data to a human on linking. Full human web UI; wired into the CI demos matrix.
- 2026-07-19: New `kiosk-demo-philslist` — a NON-COMMERCE classifieds board proving Kiosk is not only for commerce: the same query/run/schema + account-binding wire with NO payment provider, so `pay` is absent from the advertised capabilities. Its headline is cross-owner WRITE denial on owned listings (edit/close → 403) and a multi-account household (two assistants on one account); wired into the CI demos matrix.
- 2026-07-19: Discovery no longer advertises AP2/payments when the provider serves no `pay` — agents.txt drops `Protocols: ap2`/`Payments: required` and agents.json omits its `payments` block for payment-less providers, so the standard surfaces stay consistent with the computed `capabilities`.
- 2026-07-19: The advertised wire version is now 0.2.0 — Kiosk::Protocol::API_VERSION and MIN_CLIENT bump to match the 0.2 protocol, so the Kiosk-API-Version/Kiosk-Min-Client headers and the agents.json api_version now report parity with the framework release.
