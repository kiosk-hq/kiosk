# prose-counts-allow.txt -- the counts in shipped prose that bin/check-prose-counts
# does not require an inline marker for. One line per (file, count) pair:
#
#   <path> ¦ <cardinal> <noun> ¦ [from: <command> ¦] <one-line reason>
#
# THE KEY CARRIES THE NUMBER. Change "seven demos" to "eight demos" and this
# entry stops matching: the run then goes red from both ends at once -- an
# unexcused count in the prose AND an allow entry that matched nothing -- which
# is the property that makes this a record rather than a mute button. An entry
# covers every occurrence of that pair in that file, and the run prints how many
# each one covered.
#
# `from:` IS NOT AN EXCUSE, IT IS A MEASUREMENT. When present, the command is run
# from the repository root and its last numeric line must equal the number in the
# key, exactly as an inline marker is. Prefer it: an entry with a command cannot
# rot, and an entry with only a reason can. The commands run under `/bin/sh`, so
# `grep` is the real `/usr/bin/grep` over the working tree and `git ls-files` is
# what git tracks -- two different file sets, chosen per entry.
#
# Reason-only entries are for numerals that count nothing this repository can
# re-derive: a figure from someone else's document, a number inside a standard's
# name, a quantity the sentence itself enumerates in full, or a constant that
# belongs to a different artefact.
